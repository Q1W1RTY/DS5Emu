# Кандидат 0.1.33: стартовый HID-ввод

Пользователь уточнил порядок воспроизведения самонажатий в Phantom Blade Zero: сначала запускается игра, затем включается эмуляция PS5. Это локализует сценарий появления устройства в уже работающем клиенте; причина симптома ещё не доказана.

В `VirtualPort::Impl::wait_for_hid_in_frame` ожидание первого пакета ограничивалось 50 мс. После тайм-аута interrupt-IN завершался со статусом success и нулевой длиной. Такой ответ не является полным отчётом DualSense. Поскольку USB-устройство публикуется до начала обмена с физическим контроллером, этот путь доступен во время подключения.

Добавлен `HidInputSnapshot`: начальный полный 64-байтовый отчёт ID 1 содержит центрированные стики, отпущенные кнопки и курки, неактивные контакты. После получения реального пакета сохраняется его полная копия. Если очередь пуста по тайм-ауту, используется снимок; остановленное устройство возвращает -ENODEV. В очередь допускаются только полные USB input reports правильного ID. Снимок защищён существующим demux_mutex и существует в пределах виртуального порта.

Проверены начальные кнопки/оси/контакты, сохранение физического нажатия и отклонение коротких пакетов и Bluetooth report ID. Полный набор: 13 native, 57 managed, 12 профилей, 49 UI, проверки зависимостей и owned-file retention прошли. Сборки и замеры не подтверждают устранение игрового симптома: для этого требуется наблюдение проблемного порядка запуска на установленном кандидате.

Ошибка SET_FEATURE report 8 / Win32 87 остаётся отдельной неисправностью. Она не объявляется причиной самонажатий и этим изменением не устраняется. Сырые локальные аппаратные протоколы находятся в игнорируемой папке artifacts.

Кандидат установлен 2026-11-05 через штатный elevated bootstrap. Хеши UI/native совпадают с release.json. После установки контроллер Active/PS5; обычный input probe выполнен отдельно (artifacts/hotplug-installed-input.json). Игра при проверке не была запущена: игровой hot-plug регресс не принят.
