# HID, аудио и измерения в текущем форке

Это описание реализованного формата, а не отчёт о прохождении всех игровых эффектов. Первичные структуры и константы: `engine/vds/include/vds/ds5_protocol.h`, `src/vds_protocol.hh` и `src/vds_protocol.cc` внутри форка.

| Путь | Формат текущего движка |
|---|---|
| USB input | Report ID 0x01, 64 байта, из них 63 байта состояния |
| BT control input | Report ID 0x31, 78 байт; внутренний пакет с HIDP 0xA1 занимает 79 байт |
| BT microphone | 0x31 с audio payload type; Opus payload 71 байт, отдельная ветка от игрового ввода |
| USB output | 0x02 и 47 байт SetState для тестируемых команд курков/LED |
| BT state output | 0x31, 78 байт, последовательность и CRC |
| USB audio output | 4 канала, PCM int16 little-endian, 48 кГц, 8 байт на frame |
| Логические пары | Каналы 1–2: динамик/наушники; 3–4: тактильная отдача |
| Буфер PCM | 512 frames, сохранено штатное значение выбранного vDS |
| Speaker Opus | 480 frames / блок, текущий размер кодированного блока 200 байт |
| Mic PCM | Декодирование в стереопару 48 кГц для виртуального USB capture |

Перед переводом входа проверяются точный размер и CRC, включая HIDP-префикс. Битая CRC не должна становиться ложным нажатием или аудиоблоком. Тестовый эталон считает CRC побитово, независимо от таблицы production-кода.

Перевод control сохраняет 63 байта состояния с нужным сдвигом заголовка. Mute/headset/battery извлекаются из USB-представления, а остальные поля, включая тачпад и motion, передаются игре. Функциональная правильность каждого органа и датчика ещё проверяется физически.

`PcmAudioExtractor` умеет принимать USB-PCM, разрезанный посередине sample/frame. Автотесты сравнивают непрерывный и фрагментированный ввод, подают сигнал в каждый канал отдельно и проверяют отсутствие переноса haptics в speaker encoder и speaker в haptics.

Управляющий статус показывает наличие недавнего потока, а не доказанный ненулевой звук. WASAPI-probe считает frames, nonzero bytes и амплитуду по временным окнам; голос не записывается в файл. Ненулевой шум без корреляции с речью сам по себе не закрывает проверку реального микрофона/mute.

Низколатентные параметры не подбирались: штатные размеры сохранены. Задержка относительно DSX, стабильность общего clock и часовой аудиопрогон пока не измерены. Ошибки и разрывы в логах не следует превращать в недоказанный процент потерь Bluetooth.

Открытые аппаратные вопросы: детальная отдача в играх, одновременные эффекты, micro/mute, разъём наушников, BT/USB и сон. Проверять их по `docs/qa/FINAL_ACCEPTANCE.md` одним согласованным прогоном.


Ручной «Звук → haptics» использует отдельный HID report `0x32`: 142 байта, вложенный пакет `0x12`, 64 signed-PCM семпла, CRC32 с префиксом `0xA2`. Формат исследован [egormanga/SAxense](https://github.com/egormanga/SAxense). В DS5Link реализован отдельным методом существующего построителя пакетов; совмещённый игровой UAC/динамик использует прежний путь `0x36`.
