# Реализованная архитектура 0.1.0

## Процессы

- `DS5LinkBridge` — Windows-служба с C++-движком `engine/vdsd.exe` из отдельного форка vDS. В ней находятся Bluetooth, преобразование HID, USB/IP и аудиотракт.
- `DS5Link.exe` — C# / WPF / .NET 10. Окно и трей обращаются только к управляющему pipe. Физический HID интерфейс не открывает.
- usbip-win2 и HidHide — внешние общие драйверы. USB/IP сервер движка слушает 127.0.0.1:3240.

UI может быть закрыт или аварийно завершён без остановки аудио/ввода. Штатное меню «Выход» посылает pause и ждёт Paused. Недоступность связи не трактуется как подтверждение освобождения, кроме случая, когда SCM подтверждает отсутствие или остановку службы.

## Ввод и звук

Физический HID → проверка длины/CRC → распознавание control/audio → виртуальные HID/audio. Микрофонные пакеты не поступают в игровой ввод. USB-PCM остаётся четырёхканальным: отдельные стереопары динамика и тактильной отдачи; кодирование/декодирование остаётся в C++.

Игровые команды курков и LED переводятся штатными средствами vDS. Диагностические тестовые эффекты вынесены в отдельный инструмент и не являются постоянными пресетами приложения.

Виртуальный USB имеет постоянный серийный номер `DS5Link-DualSense-Port-0`. Это идентификатор одного виртуального слота v1, без MAC физического геймпада. VID/PID, интерфейсы и остальные поля дескриптора сохраняются. На трёх предварительных подключениях аудио endpoint ID не менялись; длинная серия и перезагрузка ещё требуют проверки.

## Управление и восстановление

Запрошенная пауза сохраняется отдельным marker-файлом рядом с конфигурацией. Enable снимает паузу; reconnect останавливает старый worker, сохраняя включённое состояние. Порты резервируются до завершения удаления старого worker. При пустой конфигурации выбирается один подключённый обычный DualSense либо единственный сопряжённый обычный DualSense.

Работающий DSX и настоящий USB DualSense приостанавливают захват. USB распознаётся по USB instance и исключению нашего постоянного серийного номера. Сопоставление с несколькими физическими контроллерами не является поддержанным сценарием v1.

При остановке предпринимается ограниченная попытка убрать сопротивление курков и rumble до отмены транспорта. После потери BT доставка команды не гарантируется. Старые аудио/эффекты не используются как источник новой сессии.

Обнаружение/повтор выполняются с ограниченной частотой штатного supervisor vDS. Полная аппаратная проверка сна, USB/BT и конкуренции с DSX ещё не завершена.

## Безопасность и данные

Именованный канал имеет явный DACL: SYSTEM, Administrators, SID владельца; удалённые клиенты запрещены. SID владельца передаётся службе установщиком, включая случай UAC с другой административной учётной записью. Свойство корректного отказа другому реальному пользователю Windows ещё требует системного теста.

Бинарные файлы в Program Files, машинные данные в ProgramData. Каталоги защищаются от записи обычным пользователем; owner может читать свои данные. JSONL ограничен 64 КиБ и глубиной вложенности; чтение и ответ ограничены по времени. Журнал движка ротируется: текущий файл и четыре резервных по целевому пределу 10 МиБ.

В диагностике маскируются адреса, PnP-пути и домашний путь пользователя. Аудиозаписи не сохраняются. Журнал восстановления HidHide в экспорт не входит.

Разбор заряда сверялся с форматом статуса в [Linux hid-playstation](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c): градации отображаются приблизительно, полный заряд обрабатывается отдельно, ошибки не превращаются в достоверный ноль. Заимствован формат интерфейса; код GPL-драйвера в проект не переносился.
