# Восстановление HidHide

Журнал: `<db-path>.hidhide-recovery.json`. В установленной версии он находится в защищённом ProgramData/DSEmu. Содержит schema, путь текущего daemon, instance целевого HID и признаки наших изменений: appAdded, hideAdded, cloakEnabled.

До первого изменения записывается временный файл, выполняется FlushFileBuffers, затем атомарное переименование с write-through. Только после успешной записи добавляется allowlist приложения, скрытие устройства и при необходимости глобальный cloak.

Нормальное освобождение и следующий запуск используют один путь восстановления:

1. Убрать скрытие, только если запись была добавлена нами.
2. Вернуть cloak-off, только если cloak был включён нами и не обнаружены чужие скрытые устройства.
3. Убрать allowlist, только если его запись добавили мы.
4. Удалить журнал только после успешного восстановления.

Предварительно скрытое устройство и существовавший allowlist сохраняются. Обратный режим HidHide отклоняется. Если включение глобального cloak затронуло бы другие настроенные устройства, подключение отклоняется до изменения настроек.

При изменении чужой конфигурации восстановление останавливается с сохранением журнала. По целому старому снимку HidHide не перезаписывается. Одновременные lease на несколько контроллеров запрещены.

Автотесты проверяют исходно выключенный/включённый cloak, предварительное скрытие, чужие записи, inverse mode и восстановление после моделируемой аварии. Они используют mock CLI и не меняют системный HidHide. Реальный crash/stop/uninstall и конкурирующие внешние изменения требуют финального системного прогона.

`vdsd.exe --repair-only --db-path ... --log ...` выполняет только восстановление и завершение, без подключения контроллера. Удаление сначала вызывает этот путь. Неразрешённый журнал не удаляется вместе с программой.
