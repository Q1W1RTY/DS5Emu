# Обрыв DualSense при включении PS5 с запущенной игрой

2026-11-03, локальная установка 0.1.30. Сценарий проверен на одном физическом DualSense и открытой Crimson Desert. GitHub не публиковался.

## Воспроизведение и локализация

- 0.1.29: после включения PS5 с уже работающей игрой физическое Bluetooth HID отключалось примерно через 0,3–0,9 секунды. Числовая диагностика показала Win32 1167 в HID input; последующий Win32 995 на virtual I/O — следствие отмены сессии.
- На паузе физический контроллер оставался включённым по наблюдению пользователя. Одна ранняя попытка не являлась чистым тестом паузы: enabled успел снова стать true. Это проверено и не используется как доказательство.
- Xbox по Bluetooth работал: примерно 600 пакетов/с и заряд 55%. Низкий заряд не подтвердился как причина обрывов.
- PS5 без игры работал несколько минут. Steam оставался запущенным; Steam Input для Crimson Desert уже был выключен, что подтверждено скриншотом свойств игры.
- Порядок «PS5 сначала, затем игра» временно позволял работать с нативным аудиопотоком. Но переподключение PS5 при уже открытой игре снова вызвало физический обрыв ещё до USB output-команд эффектов. Диагностическая сборка 0.1.29 воспроизвела ошибку, поэтому одно добавление журнала её не устранило.

## Дефект идентификации

USB string serial виртуального устройства был отдельным, но HID GET_REPORT 0x09 без изменения возвращал pairing/serial report физического Bluetooth DualSense. Виртуальный USB и backing Bluetooth тем самым сообщали один адрес устройства.

SDL считывает серийный адрес DualSense именно из feature report 0x09 (байты 1–6 в обратном порядке) и использует совпадение серийных адресов для предпочтения USB перед Bluetooth. Это видно в [исходнике драйвера PS5 SDL](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_ps5.c). Общая реализация сопоставления находится в [SDL_hidapijoystick.c](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapijoystick.c). В открытом SDL это прежде всего логическое отключение joystick; конкретный вызов, который разрывал физическое соединение в установленной связке Steam/игры, трассировкой процесса не установлен. Поэтому сам по себе этот исходник не объявляется доказательством физического Bluetooth disconnect.

Коллизия идентичности подтверждается кодом DS5Link; практическое исправление проверено ниже сравнением проблемного сценария до/после. Установленную версию библиотек Steam/игры не приравниваем автоматически к актуальной ветке SDL.

## Исправление

`engine/vds/src/platform/win32/vds_identity.hh`: добавлен `virtual_pairing_identity`, который для report 0x09 заменяет адрес устройства стабильным локальным виртуальным адресом своего порта. Остальные байты сохраняются; другие feature reports не изменяются.

`vds_usbip.cc`: преобразование выполняется на USB-границе ответа GET_REPORT, включая ответы из native cache. Физический контроллер, его сопряжение, исходный Bluetooth feature report и сохранённая привязка контроллера не изменяются.

Добавлены проверки стабильности адреса, различия портов, сохранности исходного массива и остальных полей pairing/firmware reports. В диагностике первые 32 USB output-команды сессии записываются с payload; Win32-сообщения содержат числовой код. Версия повышена до 0.1.30.

## Проверки после исправления

- Сборка и 13 CTest-групп, 57 managed, 48 synthetic UI-сценариев, проверки зависимостей и owned-file/backup проходят.
- Кандидат `artifacts/releases/DS5Link-0.1.30-virtual-identity/DS5Link-Setup.exe` прошёл встроенную проверку и установлен через elevated bootstrap. Хеши установленного native/UI совпадают с release.json.
- При открытой Crimson Desert включён PS5, физический контроллер подключился и остался в Active около 600 пакетов/с без ошибки.
- Два повторных `reconnect` при той же работающей игре прошли: оба вернулись в Active, около 605 пакетов/с, error пуст. На диагностической 0.1.29 именно reconnect при работающей игре воспроизводил обрыв.
- Прямое чтение GET_REPORT 0x09 из установленного виртуального HID подтвердило новый виртуальный адрес. Physical pairing этим probe не менялся.
- После переподключений input probe получил 1828 отчётов за 3 секунды, invalidReports=0.
- Конечное состояние: Active, PS5, Bluetooth, error пуст. Дополнительный output trace выключен. Игра и приложение оставлены запущенными.

Это целевая проверка обрыва и поступления ввода. Длительная игра, субъективная задержка и повторная полная приёмка звука/курков версии 0.1.30 отдельно не подтверждены; `candidate=true`, `hardwareAccepted=false` сохраняются.
